## Changes and cause

The unfinished implementation moved IPv6 suppression before the guard captures
its network baseline. Fresh attempt 19 exposed another mismatch: the bootstrap
audit still required the WireGuard IPv6 multicast route that Linux removes when
IPv6 is disabled. The corrected bootstrap audit requires exact IPv4 routes and
rejects every IPv6 address and route. Live observation behavior remains intact.
The regression failed before the fix and passes afterward. Linux documents the
address/route removal in its [IPv6 sysctl reference](https://docs.kernel.org/networking/ip-sysctl.html).

Independent review caught a compatibility regression in the unfinished code:
the pinned Tailscale TUN profile was being required on unrelated host TUNs.
Projection now retains and canonically orders bounded public TUN attributes for
host drift checks. The strict fixed profile is checked only on the owned data
`tailscale0`. A persistent multiqueue host TUN regression failed before this fix;
it now passes, while incorrect owned TUN attributes still fail initial pinning.
The reviewer confirmed the finding resolved, with no remaining Critical or
Important findings in the reviewed changes.

The transport IPv6 fault fixture also needed updating. It now proves the kernel
refuses an IPv6 default route under suppression, deliberately enables IPv6 only
on the owned test WG interface, injects a real route fault, requires audit
rejection and Offline quarantine, then restores suppression before recovery.
The failed earlier run is retained alongside the passing rerun.

## Optimization

Unchanged network snapshots now use an ordered equality fast path. Reordered
snapshots retain the exact multiset comparison, including duplicate counts.
For 128 unchanged entries the comparison work falls from **32,768 to 128**;
the resource-bound regression failed before the optimization. A separate test
checks all 14,641 pairs of sequences of length zero through four drawn from
three values against an independent sorted-copy oracle.

The [microbenchmark](audit-comparison-benchmark.json) records five samples of
20,000 comparisons per shape. For 32 ordered `u64` entries, median comparison
time changed from 227.86 ns to 2.94 ns; reversed input stayed approximately
unchanged. These numbers concern this comparison routine only. Whole-router CPU,
memory, throughput and latency improvements remain unmeasured acceptance work.
